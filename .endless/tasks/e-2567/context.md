Raised in the go-fsfix brainstorm E-2547 on 2026-11-06. go-fsfix's real repo fixtures and go-gitutil's commit operation both need an author and committer, each a display name plus an email address, and git refuses to commit without one configured. The plan had coined a go-gitutil-local "Identity" type; Mike rejected a package-local type with a generic name and chose go-dt so every package shares one type. Mike wants a struct, not a string, because a mailbox has two distinct values. Why not net/mail's Address directly: its String() renders RFC 5322 output, quoting names with commas and encoding non-ASCII names as RFC 2047, which git would store literally; git and trailers such as Co-Authored-By want the bare "Name <email>" form. net/mail.ParseAddress remains the parser. Mike chose EmailAddress as its own type because an email address is a subset of string, so a function can take one and either validate it with ParseEmailAddress or rightly assume it is valid. LocalPart, not Name, for the part before the @, so it does not collide with Mailbox.Name.
