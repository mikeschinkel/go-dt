Raised in the go-fsfix brainstorm E-2547 on 2026-11-06. go-fsfix's real repo fixtures and go-gitutil's commit operation both need an author and committer, each a display name plus an email address, and git refuses to commit without one. The brainstorm's plan had coined a go-gitutil-local "Identity" type; Mike rejected a package-local type with a generic name and chose go-dt so every package shares one type, a struct because a mailbox holds two distinct values.

Planning this task with Mike on 2026-11-10 and 2026-11-11 widened it. An email address's domain part can be an Internet domain, a single-label host such as localhost (git's default identity on a machine with no user.email is user@hostname), or an IP address literal, and go-dt's only related type, InternetDomain (a bare string type since v0.4.0, with no parser or methods), is documented for names like google.com. Mike's rule for go-dt is that a type exists to carry specific constraints: rather than widen InternetDomain, go-dt gains a family of constrained types plus broader types that the narrower ones convert to.

Mike's bar for go-dt is "what almost everyone would accept as correct", as if it could live in golang.org/x, with names taken from the RFCs wherever an RFC defines the term, and an adjective added when the bare term is too generic. go-dt's README promises a stable, dependency-free package, so anything needing golang.org/x/net goes through a caller-supplied hook or into the dtx module. Backward compatibility matters to go-dt, though Mike accepts breaking changes before v1.0 when there is a strong reason.

Why not net/mail: mail.Address.String renders RFC 5322 output, quoting names and RFC 2047-encoding non-ASCII ones, which git would store literally; and mail.ParseAddress accepts labels such as -bad- and a bare IP after the @, and drops the quotes from a quoted local part, so "john doe"@x.com comes back as an address that is no longer valid.
