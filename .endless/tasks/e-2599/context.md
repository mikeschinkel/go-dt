While planning go-fsfix's real-repo fixtures, the RepoFixtureArgs.Branch field needed a type. go-gitutil today has GitRef (used where git means a revision, which is broader than a branch name) and RemoteName. Mike asked for the git concepts to be fully modelled and reused across packages. He chose go-dt's root package over a go-dt or go-gitutil subpackage, because a second domain-types package adds a discovery burden and an import decision. He also asked that every name carry a Git prefix. Git's terms come from gitrevisions(7) and git-check-ref-format(1): a refname (refs/heads/main), a branch name (check-ref-format --branch), a tag name, a remote name, a revision (any expression naming an object, e.g. HEAD~1, main^{tree}), and an object name (40 hex for SHA-1, 64 for SHA-256).
