Endless shows every path it prints with ~ for the home directory (E-2308 in the endless project). go-dt converts a typed path value (DirPathToTilde, FilepathToTilde, EntryPathToTilde); it cannot find a path that is already inside text — an os error's "open /home/x/y: no such file", a doterr "filepath=..." entry, a fault summary stored as a sentence. Those need a text rewrite. Mike decided the rewrite is too specific for dt but fits dtx: relatively generic without having to be perfectly generic. The E-2308 session wrote it inside Endless's internal/refusal package as a stopgap, with a table-driven test; both move here as they are.

The matching rule Mike specified: the home directory followed by the path separator is replaced wherever it appears (the separator is the segment boundary, so a home of /Users/mike never matches /Users/mikey/). A bare home directory is replaced only when bounded: preceded by the start of the text, whitespace, '=', ':', a quote or an opening bracket, and followed by the end of the text, whitespace, a quote, ',', ';', ':', a closing bracket, or a '.' that is itself followed by the end or whitespace — so cwd=/Users/mike and (in /Users/mike) are rewritten, and /Users/mike.old is not. A false match in free text is cosmetic, which is why a plain text search is acceptable here and would not be in dt.

The function reads the home through dt.GetUserHomeDir, so it follows dt's contract: the app calls dt.EnsureUserHomeDir once and handles its error; GetUserHomeDir panics only when Ensure was never called. The E-2308 session misread that contract and built guards around the panic; Mike wants the contract stated in the code comments on EnsureUserHomeDir and GetUserHomeDir and in the README so the next reader does not.
